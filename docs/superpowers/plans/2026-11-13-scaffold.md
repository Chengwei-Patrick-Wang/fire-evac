# Scaffold (Python Walking Skeleton) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Before the team splits tonight, get `plan.json → building.json → sim → run.json (+ metrics)` running end to end with simple v0 modules, plus an API that serves it, so every workstream starts from working code. E builds the 3D replay against the generated examples.

**Architecture:** The Python packages `buildings`, `sim`, `fire` and `backend` live at the repo root and run from there (`python -m …`). Scripts in `tools/` put the repo root on `sys.path` and import packages normally (`tools/` is a package too). The v0 modules are deliberately simple; owners replace them (B: normalize, C: sim, D: fire).

**Tech Stack:** Python 3.12, shapely 2, numpy 2, jupedsim 1.4.2, matplotlib, FastAPI, uvicorn, httpx (TestClient).

**Spec:** `docs/superpowers/specs/2026-11-13-fire-evac-sim-design.md` (§6 contracts, §7 components). Team rules: `AGENTS.md`.

## Global Constraints

- Contracts exactly as in spec §6, and every JSON file carries `"version"`.
- Units are meters, coordinates are floor-local. Frames every 0.5 s, agent coordinates rounded to 0.01.
- All randomness comes from `numpy.random.default_rng(scenario["seed"])`. Agents are keyed by our `idx` (0..N−1).
- JuPedSim: check `removed_agents()` after every `iterate()`. Exits are zones beyond real door openings, never against a wall.
- Hackathon mode: no TDD. Each package has one `smoke_test.py`, runnable as `python -m <pkg>.smoke_test`, that exits 0 on success and prints its key numbers.
- Must run on Windows and macOS: use `pathlib` and no shell-specific code. The venv is `.venv` (Python 3.12) at the repo root.
- Never read `contracts/run.example.json` whole; inspect it with `jq` or `head -c`.

## Review Focus

1. Rooms drawn edge to edge must not merge into one walkable area: a wall gap separates them except at doors (Task S2 smoke test: R101 and R102 stay ≥ 0.15 m apart).
2. A stair room with an exterior door (E2 in the example) must yield an exit on that floor (S2: F1 has exits E1 and E2; S3: E2 gets used).
3. Agents spawned in a room must be inside the walkable area, not in walls, and not overlapping (S3: every spawn point is inside walkable and ≥ 0.5 m from the others).
4. Upper-floor agents who reach a stair are recorded with a `stair` event and never counted as evacuated (S3: F2 agents all have stair events; `evacuated` counts only exit events).
5. A run that hits `maxTime` still produces valid metrics, with t-values `null` when not reached (S3: a 20 s run returns `t100 == None` and no crash).

### Task S3: Sim v0 (per-floor sims; stairs are sinks)

**Files:** Create `sim/profiles.py`, `sim/run.py`, `sim/smoke_test.py`.

**Interfaces:**
- Consumes: building/v0, scenario/v0, and a fire object with the `fire/stub.py` API.
- Produces:
  - `run(building: dict, scenario: dict, fire=None) -> dict` (run/v0). `fire=None` means `NoFire(building, scenario)`. CLI: `python -m sim.run BUILDING SCENARIO OUT`.
  - `sim/profiles.py`: `PROFILES: dict[str, dict]` with keys `v0` (min, max m/s), `startDelay` (min, max s) and `radius` (m). Values:
    - typical: v0 1.0–1.5, delay 10–60;
    - older: 0.7–1.1, 20–90;
    - visitor: 1.0–1.5, 5–40.

    All profiles use radius 0.2.

- [ ] **Step 1: Occupants.**
  - Split `occupants.total` across rooms whose type is not corridor, stair, restroom or storage, in proportion to area (largest remainder), or use `occupants.perRoom` if given.
  - Draw each agent's profile from `mix` with `rng.choice`, then `v0` and `startDelay` uniformly from the profile's ranges.
  - Spawn by rejection sampling inside `(room polygon ∩ floor walkable).buffer(-0.3)`, at least 0.5 m from other agents.
  - `idx` runs 0..N−1.
- [ ] **Step 2: Floors.**
  - Create one `jps.Simulation` per floor (`CollisionFreeSpeedModel`, `dt=0.01`) on that floor's walkable polygon.
  - Exit stages: one per exit polygon on that floor, plus, on every floor above the lowest, one per stair polygon (v0: stairs are sinks; C replaces this with transfer).
  - Each agent targets the nearest stage on its floor by straight-line distance, with one journey per stage.
- [ ] **Step 3: Start delay.** Add all agents at t=0 with `desired_speed` 0, so they stand as obstacles (use 0.01 if 0 is rejected). At `t >= alarmTime + startDelay`, set `desired_speed = v0` and status 0 → 1.
- [ ] **Step 4: Loop.**
  - Iterate every floor sim each step.
  - After each iterate, map `removed_agents()` to `{t, type: "exit", idx, exit}` or `{t, type: "stair", idx, floor, group}`.
  - Every 1 s: call `fire.step(t)`. For each moving agent, set `desired_speed = min(v0, max(0.2, v0 − 0.34·(3 − S)))` with `S = fire.visibility(floor, x, y)`. If `fire.untenable(...)`, call `mark_agent_for_removal` and log `{t, type: "trapped", idx}`.
  - Every 0.5 s: record a frame of `[idx, x, y, floorIdx, status]` for agents still inside.
  - Every 2 s: for each floor, take `fire.snapshot(floor)`. The first non-None snapshot gives the `smoke[]` header (`floor, origin, cell, cols, rows, interval: 2`); later ones append `{t, d}`.
  - Also every 2 s, append `[t, fire.hrr(t)]` to `run["fire"]["hrr"]`.
  - Stop when no agents remain or `t >= maxTime`.
- [ ] **Step 5: Output.** Write `run/v0` with:
  - `floors` (floor ids by index), `agents[]` (`{idx, profile, floor, room, v0, startDelay}`) and `fire: {floor, x, y, hrr}`;
  - `metrics: {agents, evacuated, trapped, inStairs, remaining, t50, t90, t100, exitCounts}`. Each t-value is the time when that share of all agents has exited, or `null`.
- [ ] **Step 6: `sim/smoke_test.py`** runs the example scenario and asserts:
  - every F1 agent exits and every F2 agent has a stair event;
  - E1 and E2 are both used;
  - no agent both exits and is trapped;
  - frame times step by 0.5;
  - every spawn point is inside walkable and ≥ 0.5 m from the others;
  - running the same seed twice gives identical metrics;
  - a 20 s run (`maxTime=20`) returns `t100 is None`.

  It prints t50, t90, t100 and the runtime.
- [ ] **Step 7: Commit** `feat(sim): v0 per-floor JuPedSim runner`.

### Task S4: Fire metrics v0 and toy fire

**Files:** Create `fire/metrics.py`, `fire/smoke_test.py`, `tools/toy_fire.py`.

**Interfaces:**
- Produces: `compute(run: dict, building: dict) -> dict`, returning `run["metrics"]` plus:
  - `doors: [{id, floor, peakQueue, waitPersonSeconds, flow: None}]`, where the queue is agents with status 1 within 2 m of the door midpoint (same floor) in each frame, and wait = Σ count × `frameInterval`;
  - `heatmaps: [{floor, origin, cell: 0.5, cols, rows, d}]`: agent counts per 0.5 m cell over all frames, scaled to 0–100, as base64 Uint8, row-major from origin = (minx, miny) of the floor's walkable bounds.

  CLI: `python -m fire.metrics RUN BUILDING` prints the top 5 doors by wait.
- Produces: `tools/toy_fire.py` `class ToyFire(building, scenario)` with the full `fire/stub.py` API. **Placeholder only, so E has smoke to draw until D's model lands:**
  - On the fire floor, smoke density d = 80 inside a disk around the fire point whose radius grows at 0.5 m/s, masked to the walkable area on a 0.5 m grid.
  - `visibility = min(30, 100/d)` (30 where d = 0).
  - `untenable` is always False.
  - `snapshot` returns `{origin, cell, cols, rows, d}` on the fire floor and None elsewhere.
  - `hrr(t) = min(0.04688·t², 1500)`.

- [ ] **Step 1: Implement `compute` and `ToyFire`.**
- [ ] **Step 2: `fire/smoke_test.py`** builds a hand-made 2-agent run on the example building (both agents with status 1, within 1 m of door D101's midpoint, for 10 frames at 0.5 s). It asserts:
  - D101's `peakQueue == 2`;
  - D101's `waitPersonSeconds == 10.0`;
  - the heatmap decodes to `cols × rows` bytes;

### Task S5: API skeleton

**Files:** Create `backend/app/main.py`, `backend/app/jobs.py`, `backend/smoke_test.py`.

**Interfaces:**
- Consumes: `buildings.normalize.plan_to_building`, `sim.run.run`, `fire.metrics.compute`.
- Produces: FastAPI `app` in `backend.app.main`, with routes under `/api` (spec §7.5):
  - `GET /health`
  - `GET /buildings` → `[{id, name, source, floors}]`, and `GET /buildings/{id}`
  - `POST /buildings/from-plan` → `{id}`
  - `POST /runs` → `{runId}`
  - `GET /runs/{id}` → `{"status": "running"}`, `{"status": "error", "error": str}`, or the run JSON
  - `POST /batch` and `GET /batch/{id}` → the example batch (placeholder)
  - `POST /report` and `POST /trace/propose` → 501 `{"detail": "not implemented yet"}`
- Buildings come from `contracts/building.example.json` and `data/buildings/*.json`, plus `data/private/*.json` if present (marked `"private": true` in the list).
- Runs execute in a `ProcessPoolExecutor` (`max_workers = max(1, cpu_count − 1)`): `sim.run.run`, then `fire.metrics.compute` merged into `run["metrics"]`, then saved to `data/runs/{runId}.json`.
- CORS allows all origins (dev).

- [ ] **Step 1: Implement the routes and `jobs.py`.** Use an in-memory dict of futures keyed by `runId`. Fall back to reading `data/runs/{id}.json` after a restart.
- [ ] **Step 2: `backend/smoke_test.py`** uses `fastapi.testclient`:
  - `GET /api/buildings` contains `example-office`;
  - `POST /api/runs` with the example scenario and `maxTime` 60 polls until done (timeout 180 s), then has non-empty `frames` and `metrics.doors`.
