# Workstream E — Frontend (3D Replay, Dashboard, Risk Map) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One screen that loads a building and a run (static files or the live API), replays the evacuation in 3D with smoke, heatmap and queue rings, and answers "where would people get stuck?" with an evacuation curve, a propped-door what-if, a batch risk map and ranked weak spots.

**Architecture:** A Vite + React + TypeScript app in `frontend/`. The react-three-fiber scene builds walls from the walkable rings (one InstancedMesh of thin boxes); agents are one InstancedMesh fed by a typed-array index of run/v0 frames, and one Zustand clock advanced outside React drives agents, smoke, rings and charts. One loader reads `public/demo/*.json` (static mode) or FastAPI at `VITE_API_URL` (live mode), so the app works with no backend.

**Tech Stack:** React, TypeScript, Vite, three, @react-three/fiber, @react-three/drei, Recharts, Zustand (P1: react-markdown).

**Spec:** docs/superpowers/specs/2026-11-13-fire-evac-sim-design.md

## Global Constraints

- Contracts v0 are frozen (§6): every file carries `version`; never rename or remove a field; unknown optional fields are ignored; `types.ts` mirrors `contracts/*.example.json`, which win on any disagreement.
- Units are meters and coordinates are floor-local; plan (x, y) becomes three.js `[x, elevation, -y]` only through `toWorld` in `src/scene/geometry.ts`.
- `frames[].a` rows are `[idx, x, y, floorIdx, status]`, rounded to 0.01 m; `floorIdx` indexes `run.floors`; status 0 not moving yet, 1 moving, 2 waiting for help, 3 in a stairwell (drawn at the stair), and −1 = already out (the example writes it in the frame of an exit event): hidden; `frameInterval` is 0.5 s (A's `--thin` demo runs use 1.0 and smoke `interval` 6: use the file's values and frame times, never hard-code); an agent disappears after its exit event. Every other `floor` field (scenario, smoke, heatmaps, events, batch) is a floor id like "F1".
- Smoke and heatmap `d` are base64 of a row-major Uint8 array (0–100, `cols × rows` bytes, row 0 at `origin.y`); the smoke plane sits 1.6 m above each floor.
- Walls are the boundary of the walkable rings (`outer` and `holes`, implicitly closed): one box per segment, 0.15 m thick, floor-height tall, in one InstancedMesh.
- Door states: open, closed and propped are passable, `blocked` is not; closed doors hold smoke back. Profiles: `typical`, `older`, `visitor` (P0); `cane`, `walker`, `wheelchair` (P1).
- Performance: instancing only; matrices updated in `useFrame`; React never re-renders per frame; one rAF clock; run data is never stringified or deep-compared.
- The demo must survive bad Wi-Fi: no runtime CDN calls (no drei `<Text>` or `<Environment>`, no web fonts); static mode needs nothing but `public/demo/`.
- Ethics (§12): "Not a compliance tool" and "illustrative fire model" appear in the UI next to results; no "panic" wording or visuals; long waits are gaps in the building ("waiting at D101"), never slow people; `building.credits` is shown in the app; private buildings (`private: true`) and their runs never enter `public/demo/` or the repo.
- Hackathon mode (AGENTS.md): no TDD, no test framework; the smoke test is `npm run build` plus the task's manual check with a clean console (`npm run check-demo` joins in E9); commit small, push hourly.
- Tiers (§9): P0 = E1 to E9, P1 = E10 to E12, P2 = E13.

## Review Focus

1. A multi-MB or many-agent run file freezes the tab: frames become typed arrays once and are dropped, smoke decodes lazily, nothing renders per frame (E3: a ~30 MB stress run loads with under 1 s blocked and `<Stats />` at 30+ fps; E4 decodes one smoke frame at a time).
2. Walkable rings with holes, a repeated closing point or duplicate points (courtyards, pillars, IFC output): walls surround the holes and no zero-length boxes appear (E2: `SAMPLE_BUILDING` has all three).
3. A run with no `smoke`, `fire.hrr`, `metrics.heatmaps` or `metrics.doors` (a `NoFire` run), or with `null` t-values: layers are absent and charts show an empty state, never NaN (E4, E5, E6a: `nosmoke.run.json`).
4. Agents that change floors mid-replay or vanish (exit, stair sink, trapped): no diagonal streaks, a hop at the stair, trapped agents stay red at their last position (E3: `floorchange.run.json`).
5. The API is unreachable, slow, erroring or blocked by CORS: the page loads in static mode and Run loads the nearest precomputed run, with an error message, never an uncaught exception (E1 `detectMode`, E6b backend-off check).

### Task E37 (P0 · Sat 9 PM): Building look, floor views, visibility and agent colors (done; the steps are in the Ember plan)
- **Building:** each floor is a slab (the walkable ring with its holes as one `ExtrudeGeometry`, 0.15 m, top face on the floor plane), cutaway interior walls (white, 1.4 m), blue glass on the exterior walls with a top rail, and a translucent stair core. `classifyWalls(floor)` in `scene/geometry.ts` splits the walkable ring's segments: a segment is exterior when one point 0.6 m to a side is walkable and the point on the other side is outside every room and the walkable area. Room fills are off by default (Layers > Room colors); labels show the name and, when the name doesn't say it, the room type. A "Floor N" pill (`.floortag`) sits at each floor's front-left corner. Door colours are open #2563EB, closed #1E3A8A, propped #0891B2, blocked #DC2626; exits are #16A34A.
- **Lights:** a `hemisphereLight` replaces the ambient light. three 0.187 has no legacy lights, so intensity 1 shows an albedo at about a third of its colour: the building's materials are `toneMapped={false}` and the lights are hemisphere 1.8 and directional 1.6 (the plan's 1.0 and 0.9 rendered the slabs mid-grey, not the reference's light grey). Everything else keeps its look.
- **Floor views:** store `viewMode` (`'stacked' | 'single' | 'side' | 'ghost'`), `focusFloor` and `setViewMode(mode, floor?, fit = true)`. `visibleFloors` is written only by `setViewMode` and `flyTo` (which now means a single-floor view). `floorPlace`, `toPlaced`, `fromPlaced` and the `usePlace()` hook put every layer where its floor sits (stacked and single at `floorY`, side in a row on the ground, ghost like stacked with every floor but the focus floor at `GHOST` = 0.15 opacity). Controls: View > Floor view, the floor strip (Whole building is stacked; a floor is single, or moves the ghost focus), Layers > Floor gap (off in single and side). `explode` starts at `DEFAULT_EXPLODE` = 0.6.
- **Placing a fire:** `FirePicker` keeps one pick plane per floor, as big as that floor and at its place; in the ghost view only the solid floor takes clicks. (A plane the size of the whole building plus 10 m, as before, caught the clicks meant for the front of the floor below.) `Menu` radio options can now be disabled (Side by side and Ghost, for a one-floor building).
- **Deep links:** `v=side`, `v=ghost` (with `f`), and `f` alone for one floor; `x` is written only when the gap isn't the default, and a link without it means the default. A link that carries a camera pose keeps it (`setViewMode(..., fit = false)`).
- **Fire and smoke visibility:** `ui/VisibilityCard.tsx` (the right rail's eye button, the toolbar's Visibility, View > Fire and smoke visibility…), store `fireGlow` (0 to 2) and `smokeOpacity` (0 to 1.5). They change the picture only: `Fire.tsx` scales its size, light and emissive, `Smoke.tsx` its alpha byte.
- **Agent colours:** store `colorBy` (`'status' | 'type'`) replaces `agentColor`. `STATUS_COLORS` (green moving or in a stairwell, amber not moving yet or waiting, red trapped) and `TYPE_COLORS` (Okabe-Ito without yellow and vermillion) live in `replay/Agents.tsx`; the exit bars and the mobility table use `TYPE_COLORS` too. Trapped people also get a red ring, stairwell people are drawn smaller, waiting people keep their seconds label. The legend card lists the rows of the current scheme.
- **Exit bars** are named like the doors in the fix list and the door picker (`doorLabels`), as horizontal bars with the name wrapped on two lines; the id stays in the tooltip.
- **Brand:** `BRAND` in `ui/theme.ts` (the sidebar header, the About card, the tracer bar) and the page title read "Fireproof".
- **Frame-rate overlay:** the drei `Stats` shows only with `?perf` in the URL, never by default on the dev server.
- **QA:** `npm run qa` has the new steps `views` (the four floor views at 60 s: shots, `visibleFloors`, the pressed floor-strip item, and the same `dl.kpis` and `#replay-summary` text in every view; View > Side by side), `colors` (the legend switch) and `visibility` (the rail button, High visibility, Reset), the `deeplink` step opens `v=side`, `v=ghost&f=F2` and `f=F2`, and `a11y` also runs axe with the visibility card open and with `colorBy: 'type'`.
